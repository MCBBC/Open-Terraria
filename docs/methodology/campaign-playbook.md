# 大型工程验证长征方法论工作流（Campaign Playbook）

> 沉淀自 SandboxWorld 世界生成 1:1 对齐战役（2026-08 初 → 2026-09-06）：
> 36 条种子链 × 106 槽 × 8 通道与原版权威逐位对齐，跨约 30 个并行执行批次、
> 200+ 把「刀」，终局 VERDICT=PASS-WITH-KNOWN-DEBT，双线独立 review 通过。
> 本文把这套打法抽象为**任意大型工程**的「迭代→验证→测试→上线」工作流，
> 以本战役为案例锚（批章号引用见 `content-parity-vs-vanilla-*.md`）。

---

## 0. 总纲：一条铁律 + 五阶段

**铁律：先定谳，再动刀。** 一切修复必须先有机制级证据（源码锚/重放/物证），
禁止凭感觉、禁止「看起来像」。修复之后必须有独立于修复者的复核。
战役全期最大教训：**伪红/伪绿（环境与测量伪影）的数量远超真 bug**——
不建立反伪影纪律的团队会把 80% 时间花在追自己制造的噪音上。

```
┌────────────────────────────────────────────────────────────┐
│ P0 基建    权威源+金标库+认证网格+反伪影纪律（一次性，决定上限）│
│ P1 迭代    差分驱动最小刀 + 定罪先于修复 + 判例库             │
│ P2 验证    滚动认证 + 全量回归矩阵 + 诚实移交协议             │
│ P3 测试    永久守卫资产 + 一键门禁 + 金标冻结纪律             │
│ P4 上线    收官序列(冻结→再生→门禁→独立复核→判语→登记债)      │
└────────────────────────────────────────────────────────────┘
```

## P0 基建：地面真值基础设施（决定整场战役的上限）

### 0.1 单一权威源（Single Authority）
- 一切正确性判据锚定**一个**可执行的权威：反编译源码 / 参考实现 / 真实系统 dump。
  本战役 = 反编译 Terraria 源（双版本对照）+ x86 官方服务端（rig）可执行真值。
- 权威源要有**版本纪律**：双版本行号并注（1457/1458），基准切换时全量反向审计
  （「按旧版回滚新版特性」的刀必须反向恢复）。
- **可执行权威 > 静态规范**：rig 能跑、能 dump、能织探针——它是唯一不会骗你的证人。

### 0.2 金标库（Golden Buckets）与耐久性
- 权威输出（golden dumps）落盘为不可变基线，**存放在防清理的耐久居所**
  （本战役 /tmp 反复被系统清理灭失，迁居 home 树后止血；每次灭失都是重产成本）。
- 每桶自带账本（runbook 桶表）：配方（seed/flags/环境）、产证谱系、md5 指纹、
  验证栏。**桶的配方是认证的一部分**——配方漂移产伪红（本战役 EVIL 配方
  伪红三次翻案后才内建成门禁核对）。

### 0.3 认证网格（Certification Grid）
- 把巨大的状态空间切成**固定检查点网格 × 通道**，让「是否对齐」变成机械判定：
  - 本战役：106 槽（pass 序列）× 8 通道（act/type/wall/liq/half/slope/lty/inact），
    后扩 10ch（帧）与 paint/coat 通道——通道按需生长，网格结构不变。
- **名字锚定校验**：网格槽表必须带名字自检门（本战役 SLOT_END 错位曾把修复
  误报成回归，加 name-anchor 门后根除）。
- 每通道都要回答「x86 的这个字节是什么语义」——**编码语义先行**（如帧 -1=
  「未定帧」哨兵而非失活标记，普查前先反编译定谳，否则 228 万格假差淹没真差）。

### 0.4 反伪影纪律（Anti-Artifact Discipline）——P0 的灵魂
每种已知的伪影源配一条硬性规程，写进所有批次的操作纪律：
| 伪影源 | 规程 |
|---|---|
| 插桩扰动 | 织标后必须**中立性自证**（对金标逐字节恒等）才可用于定罪 |
| 配置漂移 | 配方逐字段核对内建自动化（冲突即拒跑，不烧链） |
| 架构/平台差异 | 交叉权威指纹（arm64 产物 md5 指纹识别，一次污染全批重产） |
| 缓存陈旧 | 转换缓存按指纹击穿；重启验证 |
| 环境衰灭 | 真值不落 /tmp；每次用桶前查在位性 |
| 代际错配 | 对照物必须同代际（跨代 lineage 假差判例 ×N） |
| 过程态 vs 终态 | 对拍口径逐字节定谳（pre-smooth vs post-smooth 假差判例） |

## P1 迭代：差分驱动 + 定罪先于修复

### 1.1 差分驱动迭代（不是需求驱动）
- 每次迭代的入口不是「想改什么」，而是**网格上最新的差分**（哪个槽红了、
  首差在哪格）。修复的价值单位 = 槽位转绿 / 差格清偿，全部可计数。
- **首差原则**：只认首差（最早的分歧点），尾段差异是首差的涟漪——
  先修首差再看级联，禁止对尾段独立落刀（会过度矫正）。

### 1.2 证据阶梯（Evidence Ladder）——定罪的升级路径
按成本从低到高逐级升级，**低级手段证伪了才允许上高级**：
1. 反编译逐句对勘（源码锚，双版本行号）
2. 离线反演-重放-自证三件套（免 rig，自校验判据达成才有效）
3. 逐掷/逐事件归属（掷账、写集差分、事件流 FNV）
4. 决定性翻转实验（把假设变量改掉看流是否不变——证伪假说最强手段）
5. rig 织标终审（兜底；织标必须中立性自证）
- 修复不是终点：**回滚判决**也是合法产出——修复不满足 1:1 时全额回滚
  并记录（净零漂移实证），宁可移交也不要近似修。

### 1.3 最小刀纪律
- 单刀 = 单一语义差异；写面刀必须**零掷**（不消耗随机流）并实证掷流零扰动。
- 高频热文件：小粒度 Edit、落刀前 mtime 复核、编辑后 grep 自己的标记复核。
- **平铺陷阱警惕**：反编译/旧代码的「字面结构」不等于真身（分支被平铺、
  结构体值拷贝是 no-op、`as unknown as` 类型放宽掩盖死字段——三类各判例在案）。

### 1.4 判例库（Precedent Library）——战役的复利引擎
- 每个根因定谳后立刻命名入库（「结构体值拷贝 no-op」「反编译平铺陷阱」
  「inActive 腿家族」「死字段读取」「值流锁步作废」「双拍结构」「多副本同步」…），
  连同**判例的适用边界**。
- 下一把刀开工前必 grep 判例库；同族问题按判例直接定罪。
- 判例被证伪也要销账（「inActive 生成期恒 0」惯例被推翻后，家族纪律改写为
  「凡 nactive/SolidTile 系谓词 JS 副本必须带腿」）。

## P2 验证：滚动认证 + 诚实移交

### 2.1 滚动认证
- 每刀落盘后立即跑认证网格（本战役 mile8：47 秒/链），红面不收敛不合入。
- **守恒判据**：新刀不得扰动已认证域（跑 2-3 条「守恒链」确认零漂移）。

### 2.2 全量回归矩阵（每批固定动作）
```
金标套件 → 护卫测试 → spot 抽查线 → 守恒链 → tests/golden 零写入审计
```
- **tests/golden 零写入纪律**：回归运行不得顺手重冻金标（重冻权在终局再生批），
  否则金标失去「不变基准」的意义。违例审计（前后 md5 快照）每批必做。
- 环境性红名单列不判罪（签名匹配既账），但签名漂移即升级阻断。

### 2.3 诚实移交协议（Honest Handoff）
- 批报告必须如实分级：**满绿 / 未达（精确到格与掷）/ 翻案 / 证伪 / 移交（刀序）**。
  105/106 就报 105/106——本战役多把刀因诚实移交而让下一刀开局即有完整弹道。
- 移交件 = 下一刀的任务书：精确坐标 + 已做/未做清单 + 仪具交接 + 已证伪路径
  （防止后车重走死路）。
- **自报不免责**：交付声明（「无遗留进程」「零写入」）用机器复核（pgrep/md5）
  兜底——本战役两次「自报干净、实际有残留」（失控 rig 烧 15 小时 CPU）。

## P3 测试：守卫资产 + 一键门禁

### 3.1 守卫矩阵（每刀必有永久测试）
- 修复落盘后审计该刀是否有**永久回归测试**（非一次性 `_` 前缀仪具）：
  - **行为面单元驱动**（合成夹具直调函数，断言掷形/写面/门序）
  - **结构锁**（源文本锚，锁死判据表达式与位序，防静默回退）
- 夹具自身的坑要入档：合成世界必须落在扫描窗内（否则断言真空转绿）、
  stub 不能「全 miss 恒 0」（反向陷阱）。

### 3.2 一键门禁（final-gate）
- 把散装认证面统合成**分阶段门禁**（本战役 S0 预检→S1 金标→S2 静态三闸→
  S3 护卫→S4 spot→S5 认证网格），两档（quick/full）、单段复跑、分阶段日志。
- 内建配方核对（配置漂移拒跑）、INVALID 形态单列（harness 崩≠对拍红）、
  零写入收尾审计、**判读基准表**（哪些红=放行域外债，哪些=阻断）。
- 门禁本身会立功：它在 dry-run 中当场捕获了并行车道的断链 import。

### 3.3 金标冻结纪律
- **「在途金标禁重冻」**：src 未定格时重产金标=让基准跟着代码漂移，门禁失效。
- 终局统一再生（P4），平时只有「再生判例规程」没有再生行为。

## P4 上线：收官序列（Endgame Protocol）

```
①src 定格 → ②金标统一再生(逐件账+确定性自证) → ③final-gate --full
→ ④独立复核(不信任自报) → ⑤红队 src 审查 → ⑥综合判语+边界声明
→ ⑦登记债账本(精确到刀序) → ⑧收官档案(报告/runbook/时间线/记忆)
```

- **独立复核**：抽链用门禁配方独立重跑、逐字节比对存档 JSON；金标 md5 链
  旧→新全对账；红名签名逐字核。**复核判语要区分「内容面」与「记账层」瑕疵**
  （记账瑕疵顺手清，不动摇结论的要如实指出）。
- **红队审查**（src 定格后、上线前）：正确性复核（点名最高风险面）、过度矫正
  侦测（两向偏差判别：该加门的没加 vs 不该加门的加了）、卫生面（休眠钩零开销/
  死字段/注释与行为一致性——「恒真/死码/不移植」类注释是翻案重灾区）、
  跨副本一致性、测试/golden 卫生。findings 分级 critical/major/minor/note，
  **只登记不落刀**（修复另派，先证可达）。
- **边界声明**（上线文案的诚实性）：明确「完成」的含义与不含义——
  含什么（36 链×8 通道逐位一致）、不含什么（部分链 10ch 全量认证、域外债清单）。
  域外债逐条归属到车道+刀序，绝不空挂。

## 组织面：多代理刀阵的运行纪律

- **编排者-刀阵**：一个编排者（派工/判读/综合），多个执行刃（各带完整任务书）。
  刃的任务书 = 背景+仪具清单+精确刀序+纪律+报告模板，让刃不依赖会话记忆。
- **并行冲突控制**：端口/产物目录按刃错开；热文件 mtime 纪律；冲突面在派工时
  显式禁触（「DungeonPass 本批禁触」）。
- **停摆恢复**：长刃可能被基础设施打断——恢复协议=断点锚+落盘笔记
  （每小步写 notes.md），续跑先读盘上状态再动。
- **进程卫生**：rig/服务类进程收官必须 pgrep 全名复核（自报不可信）；
  SIGTERM 不死升级 SIGKILL；僵尸归因父进程（外部依赖的僵尸不动）。
- **文档并发**：编号先 grep 避让、撞号照判例（先落盘者持号+顺延备案）、
  自检写入摘要（防止文档自我重复——本战役曾产 18,590 行自重复块，
  指纹定界后原子 splice 清除）。

## 反模式清单（本战役真金白银买来的）

1. **凭感觉修** → 必然过度矫正/欠矫正，返工成本数倍
2. **对尾段涟漪独立落刀** → 假修真债
3. **在途重冻金标** → 门禁整体失效
4. **信任单方自报** → 孤儿进程/漏检/伪绿
5. **低级证据未穷尽就上 rig** → 成本爆炸（先离线三件套）
6. **忽视编码语义** → 百万格假差淹没真差
7. **判例不销账** → 被证伪的惯例继续误导
8. **近似修不回滚** → 潜伏债滚雪球（1:1 或回滚，无中间态）
9. **真值放易失存储** → 反复重产
10. **把验证当一次性活动** → 没有滚动认证的合入=裸奔

## 一页速查（每把刀的 Checklist）

```
[ ] grep 判例库 + 批章定谳链（前车移交件读了吗）
[ ] 靶点反编译逐句对勘（双版本行号）
[ ] 证据阶梯走到定谳（低级证伪才升级）
[ ] 仪具中立性自证（对金标逐字节恒等）
[ ] 最小刀落盘（零掷红线/热文件 mtime/小粒度 Edit）
[ ] esbuild 秒检 → 滚动认证 → 守恒链零漂移
[ ] 全量回归矩阵 + tests/golden 零写入审计
[ ] 永久守卫测试补齐（行为面+结构锁）
[ ] 批章落盘（编号避让+判例入库+移交件精确坐标）
[ ] 进程/产物 pgrep 复核（不自报免责）
```
